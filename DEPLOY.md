# Развёртывание в Yandex Cloud

Одна ВМ, три контейнера: приложение, PostgreSQL, Caddy (HTTPS). Занимает 30–40 минут.

## Что нужно заранее

- Аккаунт Yandex Cloud с привязанным платёжным аккаунтом
- Домен или поддомен, для которого можно создать A-запись
- Секреты: токен Kit, ID кампании, входящий вебхук Б24 с правами `crm`, ID целевой стадии
- SSH-ключ (если нет: `ssh-keygen -t ed25519`, публичная часть в `~/.ssh/id_ed25519.pub`)

---

## Шаг 1. Статический IP

Консоль → **Virtual Private Cloud** → **IP-адреса** → **Зарезервировать адрес**. Зона та же, что будет у ВМ.

Адрес нужен статический: динамический меняется при остановке ВМ, а он прописан в Битриксе.

## Шаг 2. Группа безопасности

**Virtual Private Cloud** → **Группы безопасности** → **Создать**.

Входящий трафик:

| Порт | Протокол | Источник |
|---|---|---|
| 22 | TCP | ваш IP (или `0.0.0.0/0`, если IP меняется) |
| 80 | TCP | `0.0.0.0/0` — нужен Let's Encrypt для проверки домена |
| 443 | TCP | `0.0.0.0/0` |

Исходящий: разрешить всё (`0.0.0.0/0`, все порты). Без этого не будет доступа к Битриксу и Kit.

## Шаг 3. Виртуальная машина

**Compute Cloud** → **Создать ВМ**:

| Параметр | Значение |
|---|---|
| Образ | Ubuntu 24.04 LTS |
| Платформа | Intel Ice Lake или новее |
| vCPU | 2, гарантированная доля **20%** |
| RAM | 2 ГБ |
| Диск | SSD 20 ГБ |
| Публичный адрес | **Список** → зарезервированный на шаге 1 |
| Группа безопасности | созданная на шаге 2 |
| Прерываемая | **нет** |
| Логин / SSH-ключ | ваш логин и содержимое `id_ed25519.pub` |

Гарантированная доля 20% — это примерно 0,4 vCPU в постоянном режиме плюс накопленные кредиты на всплески. Для нашей нагрузки хватает с запасом, это самая дешёвая работающая конфигурация.

## Шаг 4. DNS

A-запись `kit-queue` → публичный IP машины. Проверка (TTL может держаться до получаса):

```bash
dig +short kit-queue.вашдомен.ru
```

Пока запись не резолвится, Caddy не получит сертификат.

## Шаг 5. Установка одной командой

```bash
ssh ваш_логин@ПУБЛИЧНЫЙ_IP
git clone https://github.com/Umkladet/bitrix24-kit-pds2connector.git /opt/b24-kit-queue && sudo bash /opt/b24-kit-queue/deploy/install.sh
```

Скрипт ставит Docker, настраивает ufw и swap, задаёт вопросы для `.env` (домен, почта, вебхуки, токены), проверяет A-запись, собирает и запускает контейнеры, ставит бэкап в cron и в конце ждёт ответа `https://<домен>/health`.

Токен Kit можно оставить `CHANGE_ME` и вписать позже — сервис поднимется, но не сможет отправлять в Kit, пока значение не задано. Секрет для URL робота (`WEBHOOK_SECRET`) генерируется автоматически.

Повторный запуск того же скрипта безопасен: он обновляет код и перезапускает контейнеры, `.env` не трогает. Так же обновляется сервис после `git pull`.

## Шаг 6. Если что-то пошло не так

```bash
cd /opt/b24-kit-queue
docker compose logs caddy     # сертификат: DNS не разошёлся или закрыт порт 80
docker compose logs app       # приложение: ошибки конфига видны сразу при старте
docker compose ps             # состояние контейнеров и healthcheck
```

## Шаг 7. Настройка Битрикс24

1. **Входящий вебхук**: «Разработчикам» → «Другое» → «Входящий вебхук», права `crm`. Полученный URL → `B24_REST_URL`.
2. **Робот «Вебхук»** на целевой стадии: CRM → Сделки → Роботы → «Вебхук», URL `https://kit-queue.вашдомен.ru/b24/webhook?key=<WEBHOOK_SECRET из .env>`. Значение секрета: `sudo grep WEBHOOK_SECRET /opt/b24-kit-queue/.env`. Альтернатива — исходящий вебхук по событию с «Кодом авторизации» в `B24_APP_TOKEN` (см. README).
3. После правки `.env`: `cd /opt/b24-kit-queue && docker compose up -d` (перечитает переменные).

## Шаг 8. Бэкапы

Дамп БД ставится скриптом установки: ежедневно в 03:00 в `/var/backups/b24-kit-queue`, хранится 14 дней (`/etc/cron.d/b24-kit-queue`). Отдельно включите автоматические снимки диска ВМ: **Compute Cloud** → **Диски** → **Расписания снимков**.

---

## Проверка боевым лидом

1. В Битриксе создайте тестовую сделку с контактом, у которого указан ваш телефон, и переведите на целевую стадию.
2. `docker compose logs -f app` — должны появиться строки `webhook: deal ... в очереди` и `b24: deal ... → ready`.
3. В течение минуты — `kit: отправлено 1 ...`. Ответ Kit пишется в лог целиком, проверьте его формат.
4. В интерфейсе Kit контакт появился в кампании 1576.

## Эксплуатация

```bash
cd /opt/b24-kit-queue

docker compose logs -f app                   # логи
docker compose logs --since 1h app | grep -E 'WARN|ERROR|ALERT'
docker compose restart app                   # перезапуск
docker compose up -d --build                 # обновление после git pull
docker compose exec db psql -U b24kit b24kit # консоль БД

# состояние очереди
docker compose exec db psql -U b24kit b24kit -c "SELECT status, count(*) FROM b24_kit_queue GROUP BY 1"
```

Строку `ALERT` в логе стоит завести в мониторинг: она означает, что протух токен Kit или входящий вебхук Б24.

## Что проверить через неделю работы

- `df -h` — место на диске; логи контейнеров ограничены 50 МБ на сервис, основной рост даёт PostgreSQL
- `SELECT status, count(*) FROM b24_kit_queue GROUP BY 1` — не копятся ли `b24_error` и `kit_error`
- Дампы в `/var/backups/b24-kit-queue` создаются ежедневно
